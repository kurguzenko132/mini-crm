# PilotBase

**PilotBase** — простая маркетинговая мини-CRM для запуска компании: учет ранних пользователей из разных городов и отраслей, их условий, этапов подключения, следующих шагов и ответов на маркетинговые вопросы.

## Что внутри

- Next.js App Router
- Supabase Postgres
- Row Level Security: общая база для всех (anon + authenticated)
- Добавление, редактирование, удаление ранних пользователей
- Роли пользователей: **Пользователи карты** и **Пользователи CRM**
- Поиск и фильтры по городу, отрасли, условиям, этапу и приоритету
- Страница **«Вопросы»** для маркетинговых интервью
- Единый список вопросов, которые нужно узнать у всех людей
- Роли вопросов: общий / только для карты / только для CRM
- Ответы на вопросы внутри карточки каждого пользователя
- Прогресс заполнения анкеты по каждому пользователю
- CSV-экспорт ответов по всем пользователям
- Статистика по условиям, этапам, городам и отраслям
- Блок «Сегодня нужно связаться»
- Таблица и простой вид по этапам
- Загрузка демо-пользователей
- Загрузка базовых маркетинговых вопросов
- Экспорт CSV, JSON и PNG-скриншот статистики
- Адаптивный интерфейс

## Быстрый запуск

В проекте специально зафиксированы версии зависимостей и добавлен `package-lock.json`, поэтому лучше использовать **npm ci**, а не `npm i`.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Открой:

```bash
http://localhost:3000
```

## Если `npm i` долго висит или бесконечно скачивает

Используй эти команды:

```bash
rm -rf node_modules .next
npm cache verify
npm ci --no-audit --no-fund --prefer-offline
```

В проекте есть `.npmrc`, где отключены `audit`, `fund`, прогресс-бар и включен `prefer-offline`. Это уменьшает лишние сетевые запросы и делает установку стабильнее.

Если всё равно висит, проверь сеть/VPN и попробуй явно указать официальный registry:

```bash
npm config set registry https://registry.npmjs.org/
npm ci --no-audit --no-fund
```

## Настройка Supabase

1. Создай проект в Supabase.
2. Открой SQL Editor.
3. Если база новая, выполни весь файл:

```bash
supabase/schema.sql
```

Если ты уже выполнял старую схему PilotBase, достаточно выполнить миграцию:

```bash
supabase/marketing_questions_migration.sql
```

4. В Supabase открой **Project Settings → API**.
5. Скопируй URL и anon key в `.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
```

6. Запусти проект:

```bash
npm run dev
```

7. Открой приложение, вход и регистрация не требуются.
8. Нажми **Загрузить демо** или добавляй пользователей вручную.
9. На странице пользователей выбери роль карточки: **Карта** или **CRM**.
10. Открой **Вопросы** и задай роль вопроса: общий / карта / CRM.
11. Открой карточку пользователя и заполни ответы.

## Маркетинговые вопросы

Страница **«Вопросы»** нужна, чтобы не хранить интервью хаотично в комментариях.

Логика такая:

1. Создаешь список вопросов один раз.
2. У каждого пользователя в карточке появляется блок **«Ответы на вопросы»**.
3. Заполняешь ответы после разговора.
4. В таблице видишь прогресс анкеты, например `5/8`.
5. Через **CSV ответы** выгружаешь все ответы в таблицу для анализа.

## Деплой на Vercel

Подробная инструкция лежит в файле:

```text
DEPLOY_VERCEL.md
```

Коротко:

1. Создай Supabase-проект.
2. Выполни `supabase/schema.sql` в Supabase SQL Editor.
3. Залей проект в GitHub.
4. Импортируй репозиторий в Vercel.
5. Добавь переменные окружения:

```env
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
NEXT_PUBLIC_APP_NAME=PilotBase
```

6. После деплоя настрой в Supabase `Authentication → URL Configuration`:

```text
Site URL: https://your-vercel-domain.vercel.app
Redirect URLs:
https://your-vercel-domain.vercel.app/**
http://localhost:3000/**
```
